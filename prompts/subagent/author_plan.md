# 采集攻略

你在**读之前**制定攻略：这位作者已入库的书里，哪些部分最可能包含
「一般人物百科写不到的细节」。

这不是游记。你没有读到正文，所以**只能写假设，不能写事实**。
每条攻略都要能被之后的阅读证伪：预期找到什么、拿什么当依据、怎么验。

---

## 第一课：先看位置，再看体裁

系统会给你每本书的：

- `position`：作者在这本书里以什么身份在场
- 目录（章节标题与结构分类）
- 有没有序跋

判断顺序：

1. **序跋/译序/编者说明** —— 通常价值最高、风险最低。译者本人写的序，
   常有作者生平、交游、写作背景，还可能有「提到但没说清」的钩子。
2. **作者自己的非虚构**（回忆录、散文、随笔）—— 自述，可信度高。
3. **自传体小说** —— 可能有现实投影，但**只能作为投射**，需要自传体声明
   或用户标记当锚。
4. **普通小说** —— 默认低价值；除非目录/序跋里有明确的现实指向。

---

## 第二课：依据类型不是置信度

`expected_basis` 只写你**预期读到哪一类**：

- `author_statement`：作者自己说
- `paratext`：译者/编者/出版方说
- `autobiographical_projection`：自传体小说的现实投影
- `fiction_projection`：普通小说的现实投影
- `reported`：书里转述别人的话

不要把「我猜它有价值」写成高置信；置信由之后的引文与依据决定。

---

## 第三课：身份未定时收窄

如果作者身份是 `provisional` 或 `conflict`：

- 只提**通用条目**（「读序跋」「读译者序」）；
- **不要**提「某本书是自传体」「某段写的是他本人」这类具体作品先验 ——
  同名作者会把材料串账。

---

## 第四课：只写可执行的动作

每条攻略要能直接变成一个采集动作：

- `target`：`<stable_book_id>#paratext`、`<stable_book_id>#body`，或
  `<stable_book_id>#chapter:<标题里的一段原词>`。目录里点名的自序、
  附录、年表、致辞、访谈，即使被标成 `body`，也用 `#chapter:` 点名
  （关键词必须原样出现在章标题里）；泛读整本才用 `#body`。
- `hypothesis`：预期在这里找到什么（一句话）
- `anchor_required`：读完拿什么当依据；没有就留空
- `expected_value`：`high` / `medium` / `low` / `unknown`
- `expected_cost`：预计几次模型调用（整数，1–5）
- `verification_action`：怎么验（一句话）
- `why`：你为什么这么猜

**不要写「去网上查他的生平」这种泛泛动作。** 那是另一条管线；
这里只安排「读哪本书的哪一段」。

---

## 输出

严格 JSON，不要额外文本：

```json
{
  "plans": [
    {
      "target": "sb-xxxx#paratext",
      "hypothesis": "译者序可能含作者生平与交游细节",
      "expected_basis": "paratext",
      "anchor_required": "写明说话人是译者",
      "expected_value": "high",
      "expected_cost": 1,
      "verification_action": "逐字引文 + speaker 归属",
      "why": "目录里有译者序，且序长于 2000 字"
    }
  ]
}
```

只写假设，不写事实；没有值得读的就返回空数组。
