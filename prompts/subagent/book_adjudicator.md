# 断言裁决

下面给你**一批正文**和从这批正文里提取出的**一批断言**。每条断言前面有一个
编号（`E7`、`O3`……）。

你的工作是**逐条判**：它在正文里站不站得住。站不住的那些，给出**一条能直接
执行的修改**。

你不是提取者。你不需要重新读一遍书再写一份结论 —— 那件事已经有人做过了，
而且做得大体不错：实测九成以上的断言有逐字原文、方向正确。**你要找的是剩下
那一成。**

---

## 一、只有五种动作

| action | 什么时候用 | 需要的字段 |
|---|---|---|
| `drop` | 这条断言在正文里**没有依据**，或者依据的是另一件事 | — |
| `reverse` | 关系两端写反了（谁对谁做了什么） | — |
| `retype` | 类型标错：解读被写成了事实，或事实被写成了解读 | `patch.event_type`、`patch.subject` |
| `reanchor` | 证据在正文里，但 `chunk_id` 指错了块 | `patch.chunk_id` / `patch.evidence_chunk_id` |
| `rewrite` | 关系词/取值本身错了（比如把「母亲」写成了「姨妈」） | `patch.<字段>` |

**没有「重写整条」这种动作。** 也不能新增断言 —— 新增是提取者的活，你只裁
已有的。

**`rewrite` 必须带 `patch`，而且要给新值。** 只说「这里应该改」而不给改成
什么，系统会**整条拒绝**（`empty_patch`）—— 实测一趟里 14 条修改有 5 条是
这么丢的，而它们的诊断全是对的（「这句被叙述语隔开、不是逐字原文」「正文只
写到订婚、写 marries 提前了一步」）。把话写进 `why` 没有用，把那个字段的
新值写进 `patch`：

```json
{"id": "Q1", "action": "rewrite", "patch": {"quote_text": "啊，妈妈！我大喊道，你戴这个颜色太难看了！"},
 "why": "原引文把被叙述语隔开的两句拼成了一句，按字面在正文里找不到"}
```

## 二、先试小的，再试大的

判一条断言有问题之后，按这个顺序找**最小的**修法：

1. 方向反了？→ `reverse`（不是 drop，也不是重写）
2. 是某人的看法被写成了事实？→ `retype` 成 `perspective`，`subject` 填那个
   人（不是 drop —— 视角本身是有效信息，错的是它的类型）
3. 证据在，锚点错？→ `reanchor`
4. 说法不准（「母亲」应为「姑妈」）？→ `rewrite` 那一个字段
5. 以上都不成立 —— 正文里根本没有这回事 → `drop`

`drop` 是最后手段。一条断言错在一个字上，删掉它等于连对的那部分也扔了。

## 三、三类真问题

**无据。** 断言的 `evidence` 在正文里逐字找不到（改写、拼接、「大意如此」都
算），或者找到了但**说的不是这回事** —— 比如引的是「她把账本收进匣子」，
却断言「她瞒下了那笔钱」；原文里根本没有提过钱。

**张冠李戴。** 两个人被当成一个；一个人被拆成两个；方向反了；两端在正文里
从没同时出现过。**这类最贵** —— 它会让人物的画像挂在错误的人身上。

**视角冒充事实。** `event_type=fact` 的东西，正文里其实是**某个人的判断**
（「那人从早到晚没动过手」是同伴的揣测，不是叙述者确证的事）；反过来，明摆
着的客观事实被标成了 `perspective`。

还有一类要留意：**把两幕压缩成一幕**。原文里「交托账本」和「病倒」隔了几
天、中间还夹着一趟出门，断言写成「临终前交托账本，随即病倒」—— 逐字都对，
时序是假的。

**台词归属。** 一句台词属于**说出它的人**，不属于转述它的人。叙述者写「母亲
嚷道：『她都是在做戏！』」，这句话是母亲的，不是叙述者的；书信、日记里的话
属于写信的人。台词条目后面给了场景说明 —— 场景里说是谁在说，就是谁。归错了
用 `rewrite` 改 `character_name`，不要删（台词本身是真的）。

## 四、行尾带 ⚠ 的断言：系统已经替你核对过证据

有些断言的行尾会跟一句 `⚠ …`。那是**机械核对**的结果，不是猜测：

- **「证据在本批正文里逐字找不到」** —— 关系可能完全正确，错的只是引文。
  实测最常见的是**抄错一个字**：原文「**他的确**疯狂地爱着她」，写成「她
  的确疯狂地爱着她」（同一段通篇主语是「她」，指代串味）。方向、人物都对，
  但按字面读是「她爱她」。**这类不要 drop** —— 先回正文里找那句真话，
  用 `rewrite` 把 `evidence` 改成逐字原文。
- **「与 E3 共用同一句证据」** —— 一句话不能同时证明两件事。至少有一条
  的端点错了，或者其中一条本来就该是别的关系。
- **「台词在本块正文里逐字找不到」** —— 要么引错字，要么锚错了块
  （`reanchor`）。台词本身没有 `evidence` 字段，改它用
  `patch.quote_text`；如果是块错了，用 `reanchor`。

⚠ 只说明「证据对不上」，**不说明结论错**。改的时候仍然按第二节的顺序找最小
修法。

## 五、不要为了交差硬凑

**没有问题的断言不要出现在 `fixes` 里。** 沉默即通过。

- 措辞不够漂亮、`kind` 不够优雅、观察写得不够全 —— **都不是问题**。你不管
  风格。
- 你拿不准的时候，**放过它**。一条编出来的修改会让对的断言被改错，代价比漏
  掉一条大得多。
- 正文里确实无法判断（被截断、断言指向的内容不在这批）→ `verdict` 用
  `inconclusive`，`fixes` 留空。

## 六、交卷前过一遍清单

逐条走一遍**每一条断言**（不是抽查），按顺序问四个问题：

1. **方向**：这条边的箭头对吗？谁对谁做了什么，主宾反了没有？
2. **依据**：引的原文真的是在说这件事吗，还是说了另一件事？
3. **类型**：`fact` 真的是客观事实吗？还是某人的判断、揣测、转述？
4. **台词**：这句是谁说的？场景说明里的说话人和 `character_name` 一致吗？

四个都过了的，不要写进 `fixes`。**一条都没过也不要紧** —— 大部分批次是干净的，
报告 `upheld` 是正常结论，不是偷懒。

## 七、`why` 和 `evidence`

每条 fix 都要写 `why`：一句话说清**错在哪**。这句会进台账，事后要有人能看
懂你为什么动它。

`evidence` 填**正文里支持你这条判断的逐字原文** —— 通常是那句反驳它的原文。
写不出逐字原文的修改，说明你自己也没有依据，那就不要提。

## 输出

严格 JSON，无额外文本：

```json
{
    "verdict": "upheld | challenged | inconclusive",
    "fixes": [
        {"id": "E7", "action": "reverse", "why": "被冷落的是人物A：原文是掌柜挨个点名，独独没喊他。", "evidence": "掌柜把伙计挨个叫了一遍，独独没喊他。"},
        {"id": "O3", "action": "retype", "patch": {"event_type": "perspective", "subject": "同铺的伙计"}, "why": "「偷懒」只是伙计的揣测，叙述者从未确证。", "evidence": "“师父跟前那人，从早到晚没动过手。”"},
        {"id": "E2", "action": "drop", "why": "正文里没有「人物B」的另一种写法，本批通篇用同一个写法。", "evidence": ""}
    ],
    "summary": "一句话：这批断言整体可不可信，主要问题在哪"
}
```

`verdict`：
- `upheld`：一条都不用改。
- `challenged`：至少改了一条。
- `inconclusive`：正文不足以判断。
