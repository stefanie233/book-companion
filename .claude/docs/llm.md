### 21. LLM JSON 解析

**结论**：直解 → 剥围栏 → 括号截取 → **全失败才**修裸引号；修复是最后手段

**理由**：合法 JSON 走不到修复级，故不可能改坏；修复产物另过泄漏守卫（键含引号/空串即弃）

### 22. 裸引号消歧

**结论**：引号后跟 `,` 时看后面像不像 `"键":`；数组里的逗号则一律判收尾

**理由**：只看「后跟结构字符」会把值内容里的引号误判成收尾（实测 4000 例错 1915）

### 23. 模型输出宽容三层

**结论**：**语法**（llm_json 阶梯）／**形状**（`_coerce_boundaries` 收 list 与 dict）／**取值**（`normalize_kind`、`normalize_narrative_structure`，不认识的值**照报**不装作没判定）

**理由**：换模型暴露一整类 bug：模型换个说法，功能**静默失效**。实测同书火山引擎回 `{"F#0-0":"toc"}` + `collection`，DeepSeek 回 `[{key,boundary}]` + `essay_collection` —— 前者崩在提取前（整本白跑），后者悄悄退回单域（跨篇串流原样回来）

### 24. 解析失败要重试

**结论**：explorer 拿到**非空但畸形**的响应也重试（不再「立即失败」）；`error_type` 单独报 `parse_failed`

**理由**：旧注释说「真格式错误，立即失败，不浪费重试」，账算错了：不重试的代价是**整批 5-7 块全丢**，重试只花一次调用，而解析失败本身罕见。实测某轮 65 次调用 2 次畸形 → 丢 13 块（全书 8.6%）

### 25. 另两档语法修复

**结论**：`repair_control_chars`（字符串**内**字面换行）与 `repair_fullwidth_punct`（字符串**外**全角逗号/冒号），各**独立**作用于原候选、**绝不串联**

**理由**：两种都是实测到的走形，且都无歧义（字面控制字符在字符串里永远非法；全角标点在字符串外永远不是结构）。不串联是因为：字符串**没收尾**时再叠裸引号修复，会把下一个键吞进这个字符串，产出**合法但语义错误**的对象 —— 那比解析失败更糟
