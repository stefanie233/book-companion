### 76. 跳转与恢复的优先级

**结论**：显式跳转（笔记页/浮窗批注、图谱节点「跳转原文」）统一走 `app.js jumpToPosition()`：`switchTab('reader', true)` + 自己驱动切书 + `invalidatePendingRestore()` + `whenHostVisible()`

**理由**：恢复类定位**都是延迟执行**的（`restoreViewport` 等布局稳定 ≥2 帧、`_armLateVerify` 等补载静默 ~2s）。旧实现把跳转写在 `switchTab('reader')` 之后，它们全部晚于跳转落地把视口拉回 —— 实测视口停在原处、sync 却已记下批注那一章（"点了没反应"）。另：切 tab 后**同一 tick 里阅读区仍是 0×0**，此刻定位落在零尺寸舞台上

### 77. display 的完成信号

**结论**：定位链里 `rendition.display()` 一律走 `_displayWithTimeout()`（2.5s 有界等待），**不裸 await**；跳转落点另用 section 基**核验**、未到位重试

**理由**：fork 的 display promise 会**永不 resolve**：实测切 tab 后从笔记页跳转，目标 section 已渲染、scroller 已移到位，promise 8s 不返回。裸 await 卡死整条定位链（45s 后 `jumpToAnchor` 仍未 settle，之后每次跳转都挂在 `_restoreChain` 上）。而 display 之后的收敛循环本就按几何读回校验落点，不依赖该 promise

### 78. 视口指纹跨块

**结论**：`match_page_text` 的命中判据加一级**跨块拼接**（单块包含 miss 后按章拼接、定位偏移、映射回块）

**理由**：视口顶文本横跨相邻两块是**常态**：`jumpToAnchor` 刻意把目标块首对齐到视口顶（留 24px 边距），顶行天然是「上一块的尾巴 + 这一块的开头」。旧判据恒 miss → 跳转落点被判"未命中" → 示数不回刷、进度不落库，退回跳转前的旧章（实测《窄门》ch20 ck5：指纹 = ck4 尾「…5月27日」+ ck5 首「为何要欺骗自己呢？…」，两侧都不含整串）

### 79. 图谱节点跳转

**结论**：节点详情面板「跳转原文」→ `jumpToPosition(bookId, chapter, chunk)`；`get_full_graph` 的节点带 `chunk`（first_appearance join graph_chunks 现算）

**理由**：章号是导出量、段落才是落点（只给章号会停在章首）；与批注跳转共用同一入口，切 tab / 切书 / 作废恢复 / 等可见四件事只写一处

### 80. 分支切换与上下文一致

**结论**：分叉点渲染 `‹ n/N ›`，切换 = `loadSession(兄弟会话)` 整会话替换；`get_branches` 必须带 **siblings**（同父同 fork 点）；**锚点 = fork 发生的那条消息**（重新输入→用户气泡，重新回复→agent 气泡；旧 NULL 行逐消息比对推断）；**恢复视图取族谱内 `time_updated` 最大的一支**；**后端以 `session_id` 回读会话重建 history**，前端快照只在新会话无 id 时兜底；前端 `S.chatEpoch` 作废在途流的后续写入

**理由**：分支树是按「父 + 当前」组织的，只查 children 拿不到同父兄弟；而上下文曾完全信任前端 `history` 快照 —— 界面在 B、请求发 A 的窗口真实存在（快速切换 + 在途打字机/错误兜底仍会 push）。视图可以切换得比请求快，但**写入目标与会话上下文只能有一个真相源**；`fork_point_index` 曾因 INSERT 漏列全部落成 NULL，导致整条分支链不可见 —— 索引与「从哪分叉」必须显式持久化

### 82. 阅读位置真相源

**结论**：`/api/sync` 同时收 **topSection + pageText（恢复锚）**、**focusSection + focusText（阅读意图，视口面积最大的 section）**、**visibleSections（门的上界）**；`sectionIndex → book_chapters.spine_index → chapter_index` **结构定章**，文本指纹只在该章内**定块**；**无 spine 映射时也优先用 focusText 匹配**（比视口顶尾巴更接近阅读意图）；`match_page_text` 的 hint 覆盖只留给无结构坐标的旧客户端；选区坐标（native section / chunk-mode chapter+chunk / FTS 兜底）+ **选区锚文本（±上下文，用于同名短词消歧）** 是「已见」证据，`spoiler_gate = max(阅读章, 可见章, 选区章)`，`<selection-context>` 锚到选区块

**理由**：旧链路把「视口顶第一个字」一个拟合值同时用于恢复锚、阅读进度、剧透门：章节边界上视口顶仍是上一章尾巴，指纹命中上一章，`hint` 再把下一次上报钉在同一章（自锁）—— 实测屏幕在二十四章、门卡在二十三章，模型侦察两轮才回答。`_find_chunk_by_fp` 的跨块拼接只在同章内，跨不了章；渲染层本来就有 `sectionIndex`/CFI 结构坐标，不需要「捕获屏幕所有文字」，只需要把三个问题分开回答。`spine_index` 有 4 本旧书全为 -1，且存在一章多章共存，故结构路径必须有指纹兜底；选区只给一个短词（「杨修」）会命中本章第一块而不是读者真正选的那块，锚文本把上下文一起带上

### 84. 会话按页签分线（主页 / 阅读页 / 写作页）

**结论**：三条独立会话线，指针存 `localStorage.bc_tab_sessions`（`{id, day, bookId?}`），切页只恢复**本日**的线（没有就开全新会话界面）；换书（从书架打开另一本 / 阅读页切书）清掉阅读线并开新会话。`/api/chat` 带 `page`（home/reader/writing），后端按「mode + project_id」判定会话归属：跨线 `session_id` 一律当新会话且丢弃客户端历史快照。主页请求清空阅读现场（book_id / 选区 / 进度 / 剧透门），只注入 `<home-context>`；扮演按首页线，保留书与角色卡。会话导航栏打开时按当前页预选二级页签（主页 → 全部 / 阅读页 → 按书籍 / 写作页 → 写作），只预选不锁定、顺序不变；重命名保留悬停铅笔按钮，但提示文案改成「快速双击进行重命名」，「重命名」字样不再出现（双击标题同样可改名）。

**理由**：三个界面的提示词本来就不同（home-context / reading-context / writing prompt），旧实现主页与阅读页共用一条线，且 `S.currentBook` 残留会让主页请求带上 reading-context —— 历史、标题、mode 全跟着错页。`day` 用本地日期而非会话 `time_updated`，表达的是「这条线今天用过没有」；否则隔天打开会把昨天的对话原样搬进今天。前端指针 + 后端归属校验是双保险：旧标签页、旧缓存或直接调 API 也不能把别页的 `session_id` 续写进来。

### 85. 空会话预选阅读模式 + 新会话置顶 + 导入归书架

**结论**：阅读模式是三档分段药丸（沉浸伴读 / 俯瞰分析 / 发散探索），只在**阅读页的空白会话**里浮在聊天框中央（主页 / 写作页不出现）；发出第一条消息后整块消失，该会话的模式就此冻结、界面不再提供改模式的入口。面板拖窄到放不下标签时（容器查询 320px，锚在 `.chat-body`）退化成纯图标，名字留在 `title`。选中块是一枚独立浮动的药丸，切档时整块滑过去：位移 + 挤压/拉伸走 WAAPI（约 460ms，弹簧缓动、中途 12% 以内的形变、收尾轻微过冲），快速连点从当前形变处接着走；`prefers-reduced-motion` 下直接落位。托盘（输入框上方按钮行）第一位固定是「新会话」，主页 / 阅读页 / 写作页都在。「导入书籍」从托盘移出，放到书架页「全部藏书」标题旁，只在书架出现。

**理由**：模式原来藏在阅读页的下拉里——会话开始前看不到选项，主页也没有入口。模式是**会话级**属性（换一种读法等于换一套上下文），所以放在会话开始前、跟空聊天框待在一起：第一条消息一发出就撤掉，避免中途改模式把同一段历史读成两种口径。判断「空会话」用前端状态（无 history 且无 session_id，会话懒创建）而不是 DOM 文本。导入是书库级动作，跟着书架标题走才符合归属；托盘留「新会话」这个三页都成立的动作。窄面板退化用容器查询而不是视口断点：聊天面板宽度由 splitter 决定，和窗口宽度无关。

### 86. 阅读页默认书 = 「继续阅读」真相源

**结论**：进入阅读页（点侧栏「阅读」、或刷新恢复）时，若内存里没有当前书，默认打开**书架「继续阅读」卡片那本书**（`pickContinueBook()`：`max(last_read_at, last_opened_at)` 最大者，`/api/books` 同一份数据），**不是**下拉框第一项；且 `bc_view` 必须在**选书完成之后**落盘（`refreshBooks()` 里 `await selectBook()` 再 `saveViewState()`），`restoreViewState()` 遇到 `{activeTab:'reader', bookId:null}` 也要恢复阅读页并交给 `refreshBooks()` 挑书，不得退回书架页。

**理由**：`/api/books` 的顺序是 `time_updated DESC`，与"读到哪"无关（实测第一项恒为《卡拉马佐夫兄弟》）。旧链路三处叠加：`refreshBooks` 不设默认值 → `<select>` 停在第 1 项；`switchTab` 末尾的 `saveViewState` 早于异步选书 → `bc_view` 记成 `bookId:null`；`restoreViewState` 只认 `reader && bookId` → 刷新退回书架。现象因此是"继续阅读卡片写《房思琪》，点开阅读页却是《卡拉马佐夫兄弟》，再刷新直接掉回书架"。书架卡片与阅读页各算一套"上次读的是哪本"必然漂移，两处只能共用 `pickContinueBook()`。全新书库（无任何时间戳）宁可空着，也不要按排序副作用替用户选书。

### 118. 写作页版本图（泳道）

**结论**：写作页「版本」面板的历史列表改成 `git log --graph` 式泳道图。按时间倒序一行一条提交，每列记着「这一列接下来在等哪条提交」：一条提交到来时，凡是在等它的列都接到节点（最左那列留下继续往下走，其余列画圆弧汇入），随后第一父节点接管本列、第二父节点（合并）另起一列；父提交不在可见窗口就断线，不补假线。历史默认带 `all=1`（图谱要看得见岔路）；「只看本章」从**过滤**改成**置灰**——`vcs_log(mark_chapter=True)` 给每条提交带 `touches` 布尔，整页用一棵 `tree_json` 只解析一遍的缓存算完。行高 44px 是三方常量：`writing.js` 的 `GRAPH_ROW_H`、CSS 的 `--graph-row-h`、实际行高必须相等。

**理由**：整条父子链是图的骨架，按章过滤删掉中间节点会把泳道画断，读者分不清「线本来就断」还是「被筛掉了」。颜色按**列**取而不是按分支取：同一列在时间上就是同一根线，换列才换色，这正是 git 图的读法；分支身份交给节点旁的引用胶囊（分支 / 标签 / 当前分支染强调底色）。同一行里「合并进来的列」与「第二父节点新开的列」可能落在同一列，判断竖线是否贯穿必须比前后的**值**而不是非空——否则会多画一根线，看起来像一个分支穿过了合并点。

### 119. 写作页只做「写」，装配交给 harness

**结论**：顶部动作排只保留文档级操作（撤销 / 重做 / 还原 / 暂存 / 保存 / 生成正文）。「合同」「上下文」「结算」三个按钮从页面移除，侧栏也只剩「审稿」「版本」两页；这三件事统一由写作页右侧的写作 harness 承担（`writing_create_chapter` / `writing_set_contract` / `writing_draft_chapter` / `writing_settle_chapter`）。风格诊断改从生成流的 `stage: assembled` 事件回填，不再为看诊断单独装配一次上下文。会话托盘上的「写作助手」装饰标签（无点击行为）一并删除。合同仍是硬边界：无合同点生成只提示去找写作助手，页面不再提供手写合同的入口。

**理由**：三个按钮是同一能力的第二条「手装配」路径，参数比 agent 工具更少，状态也更容易漂移。结算那条尤其糟：`handle_writing_settle` 的 422 body 是 `errors` 数组而非 `error` 字段，页面 `api()` 取不到原因，用户只看到「请求失败 (422)」，而 harness 工具会把拒绝原因逐条转述。留着 UI 会诱导用户绕过 harness，让写作页同时维护两套流程；删掉后写作页只回答「这一章写得怎么样、改过哪些版本」，流程判断回到同一个 agent。
