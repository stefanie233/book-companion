### 26. BookGraph

**结论**：Scout -> Explorer -> Recorder + SSE

**理由**：Scout 预分组省 token；Recorder 纯 SQL

### 27. 叙事域划分

**结论**：context_setter 看目录判集类 × 机械守卫（标题带序号/单元吞半本）；两份都点头才划，否则单域

**理由**：Scout 的 narrative_units 是**情节节拍不是世界**（窄门 8 个＝序幕/高潮/尾声），拿它划域会把长篇按幕切开；单域时全链路零改动

### 28. 叙事域的作用范围

**结论**：**只做两件事**：批次不跨域 + user message 带域简报。**实体索引与证伪名册都不按域过滤**

**理由**：过滤的代价是**复现实体被反复重命名**：提取第 7 篇时看不见第 1 篇已建的「我」，于是给同一个人另起「史铁生」—— 实测《我与地坛》叙述者裂成三个节点。防串流靠「一批不跨篇」，不是靠把环境藏起来；藏起来是失忆，不是隔离。且自传性散文集里跨篇连线**本来就该有**（叙述者/母亲横跨各篇）

### 29. 提取提示词

**结论**：`prompts/subagent/book_extractor.md` 五课教学口吻；`explorer.py` 只留最小兜底

**理由**：教方法不教答案；旧提示词把「kind 可自由扩展」写死在代码里

### 30. 实体准入（孤儿）

**结论**：`new_nodes` = **声明的**实体，只有被引用的才建节点；没被引用的进缺陷清单回炉

**理由**：孤儿由构造消灭（存量 17% degree=0）

### 31. 实体准入（悬空边）

**结论**：**对称的另一半**：被引用却没声明的名字，**兜底建节点**（`kind=unknown` + 上报），不丢边；提示词同步删掉「不要重复声明」这条禁令

**理由**：两个不同模型都只声明「新」实体、引用「已有」实体 —— 是任务框架的缝不是模型的错。实测《我与地坛》28 条边只落地 3 条，丢的两次都是「我」「母亲」「地坛」。按第二课定义，边的端点**就是**实体

### 32. kind 去重 + 词表

**结论**：同名跨 kind 复用落 `upsert_node`（SQL）；变体/同义词归一，词表外**原样保留**并上报

**理由**：提示词会漂 SQL 不会；`person`(332) 与 `character`(520) 并存会让角色内核**静默**失效

### 33. 提取回炉环 → 裁决环

**结论**：**不再重提整批**。提取一次 → 机械修补（别名无据/锚点出批/同批重复/书名号变体）→ 证伪者对**带编号的断言**下五种可执行判决（drop/reverse/retype/reanchor/rewrite）→ 机械执行 → 再体检。旧回炉模式保留在 `repair_mode="rework"` 供回退

**理由**：旧环实测**不收敛**：窄门 14 批里 13 批跑满 3 轮，三轮之间边逐字稳定率 **19%**、观察 **1%** —— 每轮都是重掷骰子。而证伪提的问题是真的（别名「热罗姆」全书 0 次、母亲私话「装病」被写成事实、关系方向反了、两幕压缩成「临终前随即去世」）；用「整批重提」去修「某一条断言」，把 81% 正确的内容一起扔了。改后调用 −49%、输出 token −65%、墙钟 −60%，gold 召回反而升

### 34. 骨架趟

**结论**：逐批提取前，先让模型**看整本书**，只产出小而稳的东西：规范名、别称、一句话身份、结构关系（亲缘/社会/情感/空间）。产物落库后，批次的名字索引里就带着它

**理由**：批次提取看不见**结构**：它的单位是一幕戏。人工 gold 45 条关键关系里基线只命中 62%，漏的几乎全是骨架（三组姐妹、三组父子、夫妻、收养、谁在哪读书）。骨架把 gold 召回推到 **76–80%**，并且让「母亲」这类称谓有确定的归属（别名 → 规范名）

### 35. 骨架身份不写结局

**结论**：`identity` 只写「一出场就成立」的事；后续由带章节锚点的观察/关系记录。`record_skeleton` 用 `invariants.finality_hit`（`FINALITY_WORDS`：去世/已故/离世/安葬/嫁给/最终/后来…）把可疑身份记进 `identity_warnings`，**连锚点章号一起报**

**理由**：身份说明会**无条件**进角色卡（`format_role_kernel` 不按章过滤）。实测模型写的「最终在疗养院病逝」「后嫁给爱德华」等于在第一章摊开结局。词表是**启发式不是判据** —— 它的作用是把可疑条目捞出来；带章号是因为「落在末章」与「落在开头」是两回事（实测窄门 3 条命中，全在 ch20，无害；不分章报会被噪音淹掉）。漏词的代价是静默：「以**已故**阿莉莎的名字命名」在旧词表下一条都不报

### 36. 边去重

**结论**：`add_edge` 的键是 `(project, src, tgt, kind, event_type)`，重复写入只 `occurrences += 1` 并把锚点挪到**更早**的块；`event_type` 进键是因为「他是她哥哥」（fact）与「她觉得他是她哥哥」（perspective）是两句不同的话

**理由**：旧唯一键含 `chunk_id`，而持久关系的本质就是**每一批都会再看见它一次** —— 实测窄门 241 条边里 89 条（37%）是同一关系的拷贝（「杰罗姆 loves 阿莉莎」7 条），图退化成事件日志。在真实数据上模拟去重：152 条边，gold 召回一条不少（36/45 不变）。锚点取**更早**是因为剧透门问的是「读者最早能在哪知道」，不是「最后一次被提到」

### 37. 提示词示例必须是虚构的

**结论**：三个图谱提示词的示例人物一律用**虚构**角色（沈砚 / 祁元朗 / 沈荷），示例正文也自己写；**不许用任何真实书目的原文、真名和章号**。对照示例在文件里只是「形状」

**理由**：旧 `book_skeleton.md` 的输出示例就是窄门的答案：`阿莉莎·布科兰 / [阿莉莎, 表姐] / 「布科兰家长女，杰罗姆的表姐」/ chapter 13` + `阿莉莎—朱莉叶特 sibling_of` + `布科兰—阿莉莎 parent_of`，逐字对上人工 gold 的 g06 与 g09。拿它当基准，等于把答案抄给考生 —— 实测去污染后 **边命中 36 = 36 一条没掉**（干净跑那趟骨架趟还整个失败了），说明这轮成绩不是抄来的，但**当时无法证明**，这就是要防的东西

### 38. 提示词不许有体裁偏向

**结论**：实体清单与「查一遍名册」按体裁分档：叙事类查血亲/姻亲/养亲/**师从·主仆·同盟·敌对**；论说类收概念与机构，`relations` 允许为空。名字示例用「沈砚的母亲」这种**带具体名字**的形式，不用抽象的「某某的母亲」

**理由**：「四问」原版是 19 世纪家族小说的骨架，对《人类简史》《身体不是忘记》四个问题全空。但要保住**具体性**：改成抽象的「某某的母亲」后，模型直接照抄裸称谓，一本书里冒出「母亲」和「杰罗姆的母亲」两个节点

### 39. 限流不是抖动

**结论**：429/`RequestBurstTooFast` 走 `THROTTLE_BACKOFF=(20,45,90,180,300)` 秒并把重试次数放宽到 6–8；普通错误仍是 1+2 次、2/4 秒。`BATCH_CONCURRENCY` 可用 `BC_GRAPH_CONCURRENCY` 压到 1

**理由**：实测一趟 44 次 429，重试间隔只有 2/4 秒 —— 对 **burst 增长**保护等于没有退避，三次耗尽后**整批 5–7 块正文静默丢失**（窄门丢了 2/14 批，顶层照打 `done`）。并发只影响墙钟，不影响产物

### 40. 机械体检要送进裁决

**结论**：`evidence_flags(result, chunk_text)` 在裁决之前逐条核证据，四类问题以 `⚠` 标在断言行尾：证据逐字找不到 / 锚点错但在别块找到 / 与另一条共用同一句证据 / 台词逐字找不到。裁决提示词明写「⚠ 只说明证据对不上，不说明结论错，**不要 drop**，用 rewrite 改 evidence」

**理由**：逐字校验早就发现了「她的确疯狂地爱着她」这类错（原文是「**他**的确」，同一段通篇主语是「她」），但 `quote_unverifiable` 非阻塞、`_fix_anchor` 只在「别块能找到」时才动，于是它对裁决者**不可见**。实测：加体检前 14 批裁决全程 `fix=0/0`、证据逐字率 98.6%/99.3%；加体检后 11/14 批动手（提 14 条、落 9 条），证据逐字率 **100%/100%**，那张错引的边被改回原文或删除。「共用证据」会误报（原文「我的表姐和表妹」本来就同时提到两人），所以只报不拦 —— 实测裁决者对该改的改、该放过的放过

### 41. 被拒的修改要回灌一次

**结论**：`apply_fixes` 拒收（`empty_patch`、白名单外字段、reanchor 出批）后，若本轮有拒收就**再问一次裁决者**：同一份正文 + **改动后**的断言表 + 驳回账单（`{id, action, why, reason}`），只补一轮不递归；日志 phase 记 `adjudicate_retry`。旧编号明确作废

**理由**：只有一轮时裁决者永远不知道自己的修改没落地。实测 14 条里 5 条被拒，原因全是「只写 why、不给 patch」，而诊断本身是对的（「这句被叙述语隔开、不是逐字原文」「正文只写到订婚、写 marries 提前了一步」）。台词还有第二个坑：台词没有 `evidence` 字段，模型按提示词写 `patch.evidence` 会被白名单静默拒 —— 已在 `_PATCH_ALIASES["quotes"]` 给它 `evidence → quote_text` 的落点

### 42. 飞行记录仪存思维链

**结论**：`graph_llm_logs.reasoning_content`（迁移 13），取 `choices[0].message.reasoning_content`，非推理模型存空串；五个调用方（explorer / skeleton / adjudicator / verifier / scout）都接。飞行记录仪详情页多一块「思考过程」

**理由**：只记 `reasoning_tokens` 等于只记「想了多久」。实测一次提取调用 62% 的输出是思考（4,439/7,179），而错的那一步在思考之外（抄错代词）—— 要回答「它当时在干什么」必须有正文。按 run / phase 取帧的接口本来就有（`llm-runs` → `calls?phase=` → `calls/{id}`），缺的只是这一列

### 43. 空骨架不是成功

**结论**：`_run_skeleton_phase` 在 `entities`/`relations` 皆空时把 `stats["ok"]=False`、事件标签写「骨架（失败）」并 `log.error`

**理由**：实测骨架调用被限流打掉后落库的是「实体 0 · 别名 0 · 关系 0」，台账却写 `done` —— 下游只看到「这本书没有人物」，后续批次拿不到规范名与亲缘边也没人知道

### 44. 身份说明先写者赢

**结论**：`upsert_node` 的 `description` 默认只填空、不覆盖（`overwrite_description=True` 才覆盖）。骨架先写，批次补空

**理由**：批次写的 `why` 是**本批视角**的一句话（实测有「本块未出场，但…」），逐批覆盖会让角色卡第一行永远停在最后一章的临时判断上

### 45. 角色卡的关键关系

**结论**：`get_node_detail` 按 (方向, 对方, kind) 合并并记 `occurrences`/`other_degree`；`format_role_kernel` 按「持久关系优先 → 对方度数 → 出现次数 → 章号」取前三，同一对方最多两条

**理由**：旧实现直接取 `relations[:3]`，而底层按章号排序 —— 实测阿莉莎的卡上全是 `studies_with`/`asks_secrecy`/`comforts`，真正定义她的 `loves`/`sibling_of` 排在几十条之后看不见

### 46. 关系词表

**结论**：骨架趟与批次提取器**都用** `RELATION_KINDS`（约 55 个词，见 `invariants.py`）。边只写跨场景成立的关系；一幕戏里的动作交给 `chunk_summaries`，结局类事实写成观察

**理由**：旧图 585 条边用了 **415 种** kind，只有 **17.4%** 是持久关系 —— 每个关系词只出现一次，查询和合并都用不上它，「她和谁是什么关系」在库里问不出来。换词表后窄门 226 条边 / **38 种** kind，亲缘结构完整。代价：不在一幕戏里的同类事实要另找落点，所以同时补齐「人生阶段/身份」与「结局类事实」两条指令

### 47. 书名号变体

**结论**：`upsert_node` 在**同 kind** 下把 `《X》` 与 `X` 视为同一实体；跨 kind 不合并

**理由**：同一本书里两种写法会各建一个节点（窄门实测 `《圣经》` 与 `圣经` 并存）；但《窄门》work 与 窄门 concept 是两回事

### 48. 缺陷分阻塞/提示

**结论**：`Finding.blocking`：只有**阻塞项**触发回炉，提示项只进反馈文本；选轮排序 `(阻塞数, 质疑数, -内容量)` 字典序

**理由**：回炉是最贵的一步。为「写库时就会被归一掉的东西」烧一轮重提取是纯浪费（`kind_drift` 占缺陷 59%、落库影响 0）。字典序而非等权相加 —— 证实的优先于存疑的，且同分偏好内容多（否则奖励删东西）

### 49. 引文共用锚点判据

**结论**：「多引文同一锚点」**且**「至少一条并不真的在那块里」；没给 chunk_text 时退回前半句

**理由**：密集对话段天然多条引文同块（实测《秋天的怀念》843 字一块里 5 条台词，逐字全对）—— 只看前半句是误报

### 50. 逐字证据

**结论**：`evidence_text` 列（迁移 8）+ 三层断言检查：无锚点 / 无原文 / 原文在自己锚定的块里找不到

**理由**：锚点只说「在哪」，说不出「凭什么」

### 51. 锚点首现块

**结论**：`first_appearance_chunk_id` 是**导出量**：`recorder._first_mention` 逐块扫批次正文算出；提示词里已**删掉**该字段。没给 `chunk_text` 时才退回模型自报值 → 引用块兜底

**理由**：模型填的是「这条断言引的 evidence 所在块」。证伪器为此报了 14 条质疑（占全部质疑 10%），每次烧一整轮重提取，去改一个系统一秒能算对的字段。**导出量不该让模型猜** —— 和「统计是读的代理」同一条道理

### 52. 实体重要级

**结论**：**不落库**。目前只有「度数」这一种形态，现算现用：前端 `nodeSize`/`isCoreNode` 画大小与光晕、索引 detailed 层选 24 个带别名、`get_node_detail` 同名消歧

**理由**：重要级是导出量，落库就会过期。且它**必须篇内相对** ——「母亲」在《秋天的怀念》是第一主角、在《好运设计》是虚构的来世母亲，全局标量把两者压成一个数。实测《黄土地情歌》篇内 top4（年轻朋友的父亲/知青/年轻朋友的母亲/插队）**一个都不在全局 top12**。提取结果本身不扁平（`我` 度 192 vs 路人 1），扁平的是 schema 与消费层。等真有消费者（选角/画像/主要人物列表）再建

### 53. 读者笔记

**结论**：新表 `graph_notes`（迁移 9）**不落 observations**；`node_id` 可空；`chunk_id` 先纠锚再校验；生成侧**只给本篇正文**（生成门是结构性的 —— 看不见就是看不见）；披露门按章号下界。设计稿 `docs/reader-notes-design.md`

**理由**：笔记是 agent 自己的，和「关于角色的事实」是两种东西 —— 混表会漏进 `format_role_kernel` 的「关键观察」**和** recall 的 `<user-notes>`（那张表已被两个通道消费）。实测《我与地坛》46 条：**12 条（26%）无节点**（写作手法 / 段落反应），硬塞节点会让它写变形；2 条锚错同章兄弟块（引文逐字为真，逐字校验抓不住）—— `chunk_id` 和 `first_appearance_chunk_id` 一样是**导出量，不该让模型猜**

### 54. 索引 detailed 层

**结论**：就近档（首现章 ±2）**只钉 `character`**；其余按度数+观察数排

**理由**：**量出来的，不是随手写的。** 曾改成「钉所有 kind」，实测更差 —— 尺子是「24 个名额里有几个是**该章正文真的出现、且带别名**的实体」：原版 46、改后 39。硬分档让就近的非人物占满名额，把 `我`（8 章）、`地坛`（3 章）这些**有别名的枢纽**挤出去（它们原本靠第二关键字进榜）。加成式（就近度数×2/×4）得 43/47，相对原版没有像样增益，不值得为一个实体引入魔法系数。**只影响排序、不影响可见性**

### 55. 读取路径的名字解析

**结论**：`GraphDB.locate_node`（**精确别名 → 精确正名 → 子串度数优先**）四处共用：`get_node_detail` / `find_path._locate` / `search_nodes` / `search_all`；后两者另加 `_SEARCH_ORDER`（精确名优先 → 度数 → 名字定序）。**写入路径的 `name_to_node_id` 保持只做精确匹配，两者不合并**

**理由**：别名**写入路径认、读取路径一处都没认** —— 实测 34 条别名里 `史铁生`（叙述者「我」，度 315）、`小公园`（地坛）、`白鸡脖`（B校长）三条工具路径全部返回「未找到实体」。不能共用写入路径的解析器：那里退到子串会把「母亲」并进「你母亲」，是数据损坏。另：`search_all` 原先**没有 ORDER BY**，`limit=2` 取到「你母亲 + 八子的母亲」，真正的「母亲」（度 78）排第 4 —— **同一个问题 `get_node_detail` 对、`graph_search` 错**，不一致本身才是 bug

### 56. 存量 kind 归一

**结论**：`normalize_kind` **只在写入时生效**；旧库靠 `scripts/repair_graph.py --kinds`，且**必须先 `--merge`**（同名不同 kind 归一后会撞 `UNIQUE(project_id, canonical_name, kind)`，检测到碰撞就跳过不硬改）

**理由**：`kind='character'` 是三处硬编码，用了 `person` 的旧库**扮演模式整个是死的**：实测《身体从未忘记》1971 条边、484 条观察全在，**0 个 character** —— 归一后 0→332。**kind 变体是「读取路径看不见语料」，与别名同一个形状**；不是语料不够，是工程债

### 57. `merge_nodes` 的搬运范围

**结论**：必须搬 **边 + 别名 + 观察 + 笔记 + 首现块（取章号更早的）**；计数用 `cursor.rowcount`，**不用 `conn.total_changes`**

**理由**：原先只搬边和别名 —— 被并掉节点上的**观察会指向一个不存在的 id，永久失联**（观察是角色内核的唯一来源，等于把画像删了）。`total_changes` 是**连接级累计值**，实测一本只有 10 条观察的书报出 `obs_moved=4971`

### 58. `nodes_fts` 列名

**结论**：必须是 `id`（= `nodes.id`），**不能叫 `node_id`**；FTS5 影子表（`*_data`/`*_idx`）不进迁移台账

**理由**：external-content FTS5 按**列名**回 content 表取值，声明一个 content 表上不存在的列名会让整张表**任何查询都抛**（连 `COUNT(*)` 都不行）—— `search_nodes`/`search_all` 的 FTS 分支因此**永远**掉进 LIKE 兜底，前缀匹配与 BM25 从未生效，而 docstring 一直写着「FTS5 prefix match」。触发器写的是 `NEW.id`（**索引侧一直是对的**），这个不对称正是它藏得住的原因。影子表是索引页结构，`rebuild` 必改其行数，而数据丢失的信号在内容表上

### 59. 剧透门

**结论**：上限 = **0-based `chapter_index`**，判据 `ch <= max_chapter`；**全流程唯一一处计算**在 `api_server`（roleplay 用前端显式门、其余模式用读者当前章），图谱工具/角色内核/观察召回都读同一个值；`max_chapter=-1` **被夹住**（只在无门时才是全书）；**无锚点（`ch is None`）一律不展示**，只单独计数

**理由**：四处曾经各错一处，且**每一处单独看都像是对的**：(a) `roleplay.js` 写 `currentChapter + 1` —— **差一章**，读者在《秋天的怀念》(idx 7) 放行《墙下短记》整篇；(b) 阅读模式下 `max_chapter` 是 `None` —— **根本没门**，而工具描述一直写着「默认只含读者当前进度（防剧透）」；(c) `graph_node(max_chapter=-1)` 直接落成 `None` = 全书视角 —— **门的开关在模型手上**，被追问「后来呢」时一次调用就泄；(d) `ch is None` 当「已见」放行（fail-open），实测《地下室手记》19/19 条观察无锚点 = 该书剧透门 100% 失效。**「代码负责约束」的检验标准是不存在旁路** —— 连 `formatter` 里那句 `查看完整 -> graph_node(name, max_chapter=-1)` 都是在把钥匙递给模型。无锚点是**正确的代价**（定位不到时间线就无法证明安全），但要计数报出来，不能静默丢

### 60. 搜索不含章节节点

**结论**：`search_nodes` / `search_all` 一律 `AND n.kind!='chapter'`

**理由**：`get_full_graph`、`invariants`、`notes.roster_for` **全都**排除了章节节点，**只有搜索没排** —— 实测 `search_all('地坛')` 把 `我与地坛[chapter]` 当实体返回、`search_all('目录')` 返回章节节点。全库 484 个章节节点，零边、零观察、零消费者

### 61. 图谱观察召回

**结论**：`_fetch_graph` **先分词**（`_query_terms`：jieba + 2-gram，真词在前），再**实体优先 + 关键词兜底**两趟；每实体/每词最多 2 条；输出带 `[field·实体名]`

**理由**：`search_observations` 是**关键词**接口，调用方却传**整句用户消息** —— `observations_fts` 是 trigram，`MATCH '<整句>'` 退化成整句子串搜索，LIKE 兜底同理。实测 6 个真实问法**全部 0 命中**（而「母亲」「地坛」「轮椅」这类关键词有 5/1/5 条）——**这条通道一直是死的**，只在「整条消息恰好是某条观察的子串」时才亮。两趟都必要：实体那趟能带上「这是谁」（观察值常常不带主语），关键词那趟补「实体自己没观察、但别人的观察提到它」（「地坛」「生命」都是这样）。**分词放调用方**，检索层不 import 分词器（与 `tools._tool_graph_context` 同一分层）

### 62. 图谱输出预算

**结论**：五处调用统一走 `bookgraph/llm_call.output_budget(cfg)`（默认 64000，`graph.max_tokens` 可覆盖）；`finish_reason=length` 报 `truncated` 并抬预算重试（上限 256k）

**理由**：写死 16000 时推理模型光思考就 15k，正文一个字符轮不到，端点回 **HTTP 200 + 空 content** —— 被误诊成「模型没说话」，重试三次后整批丢弃（实测 10 次挂 7 次）。掐推理模型的预算，失败模式是**没有答案**，不是答案变短

### 63. 悬空引用

**结论**：被引用却没声明、库里也没有的名字 → `unresolved_reference` 缺陷 → 回炉；提示词硬约束「写进边/观察/引文的名字必须已声明或在索引里」

**理由**：一条边只要一个端点落空就**整条蒸发**（实测《我与地坛》某批 28 条边只落地 3 条）。旧提示词说「索引里的实体不用重复声明」而准入闸只给声明过的建节点 —— 两半契约互相矛盾，且自我强化

### 65. 角色信息注入

**结论**：format_role_kernel() 纯函数 -> system prompt

**理由**：f9743b3 起废弃 LLM 生成 + 文件缓存

### 66. 图谱存储

**结论**：graph.db (nodes/edges/aliases/quotes/merge_candidates)

**理由**：name->alias 解析链

### 81. chunk 简述

**结论**：`book_chunks.summary`（books.db 迁移 24）；**由 Explorer 顺手产出**（输出里的 `chunk_summaries`，每块 20–60 字），任一轮拿到就收、后轮覆盖前轮，采纳轮漏写时保留前轮的；`library_search` **有简述就不回原文片段**，空简述退回片段；存量与漏写由 `scripts/backfill_chunk_summaries.py` 补

**理由**：简述属于**书层**不是图谱层：没有图谱的书也该有，消费方（检索/当前段落/历史压缩）全在 books.db，放 graph.db 会让每次读都跨库 join。不做单独一趟提取 —— 提取器已经逐字读完这一批，再开一个模型重读只会换来一致性下降。写入只填 `summary=''`（重提取不覆盖已有值）；重导时同坐标 + 正文逐字相同才沿用（`insert_chunks`），否则重导一次全书简述全丢。**不能认 `summary`（单数）字段** —— 那是「本批完成情况」的台账行。模型常把裸 dict 再包一层 `{"chunk_summaries": {...}}`，不拆包会被静默丢光（实测补录首趟写入 0 条）。模型还会重写 chunk_id：`chunk_001` 序号或 `chunk_<真id>` 前缀 —— 归一化按批次顺序对位 / 去前缀修复，**序号修复只对有序列表生效**（set 的迭代顺序任意，对位会把简述安到错误的块上，比丢掉更糟）；提示词示例里写 `chunk_001` 是这类走形的直接来源（实测三本书覆盖率 62%/59%/33% → 修复后 100%/100%/100%）
