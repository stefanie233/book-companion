# 阅读会话域

### 124. 阅读会话：正文资料的主生产线

**结论**（2026-10-29 原型落地）：新增独立 `reading/` 包与
`scripts/run_reading_session.py`，按章细读，产出「rich note + compact」；
先服务**场景解释**与**角色扮演内核**，写作透镜排后；图谱退为投影/索引。

- **上下文**：稳定 system（版本 `READING_PROMPT_VERSION`）+ 逐章追加
  user 正文 / assistant 笔记。阈值 = 模型窗口 × 35%
  （`Config.context_alert_ratio`）；超了才换窗 = 摘要块（compact）+ 最近
  3 章原文，一次 miss，之后前缀重新稳定。5 章小样 0 次换窗。
- **工具**：`search_book` / `read_passage` / `verify_quote` / `coverage`，
  全部以 `current_chapter` 为硬门，未来章一律拒绝；写笔记时机械逐字核
  引文，未命中直接丢弃并记 `unverified_quotes`；引文锚点取最早出现的章。
- **笔记契约**：scene / characters（含 aliases）/ relations / facts /
  quotes（逐字 + 章/块）/ threads / reading / compact。整份 500–700
  tokens；compact <=160 字，只进换窗摘要。
- **消费**：`ReadingStore.notes_for(as_of)` → `scene_view()`（伴读，只取
  截至当前章）与 `roleplay_kernel()`（合并角色状态、别名、关系、事实、
  声音样张）。两者都是纯投影，不调模型。
- **存储**：原型隔离在 `data/reading.db`（reading_runs / notes / resets），
  不往 books.db 加表；字段稳定后再决定并库。
- **飞行记录仪**：每次调用把 system + messages + 响应（含 `<think>`）+
  模型/延迟写 `context_log.db`，会话 id `reading:<run_id>`，
  `mode=reading-vN`；提示词微调与工作流复盘直接看这里。
- **检查器**：`python scripts/inspect_reading_run.py 参考书B` 看整本账；
  `--chapter 7 --calls` 看该章模型收到的任务、工具调用、思维链与笔记。
- **续跑**：`--resume` 只复用同 `prompt_version` 的笔记；已完成章以
  compact 重建前缀摘要，跳过后从断点继续。

**实测（参考书B，2026-10-29/30）**：

- **全本 80 章**（书名页 21 字被 min_chars 跳过）：81 次调用、0 失败、
  0 换窗；输入 6,355,021，命中 5,938,560（**93.5%**），未命中 416,461；
  输出 127,405（推理 56,482）。命中率末段 92–99%，前段低（第 11 章
  20%、第 17 章 48%）是 provider 缓存写入/尾部未命中，不是提示词变化。
- 质量：231 条引文、4 条未核（1.7%，抽查均为改写句，校验器丢得对）；
  208 人次角色、108 条关系；每章 facts 4.95、quotes 2.89、threads 4、
  scene 74 字、compact 100 字、reading 75 字；0 空 scene、0 空引文。
  8 章没有新关系（第 25/36/39/42/59/72/76/80 章）——提示词要求只写
  「本章确立或变化的关系」，不重复旧关系，属预期。
- 模型实际姿势：每章 1 次调用、0 工具调用；system 1,571 字符；user =
  整章正文 + 「已读此前 N 章；本章 X/80 章」；模型在思维链里用英文
  梳理，再输出中文 JSON。工具只在需要回查前文时才会被调用。
- 早期小样：5 章 7 次调用、命中 62.1%、输出 8,664（推理 4,187）；
  v3 单章 1 次调用、0 工具、输出 3,084（推理 2,347）。

**实测（参考书A，2026-10-30，8 章全本）**：

- 8 章 / 8 次调用、0 失败、0 换窗；输入 237,099，命中 136,016（**57.4%**），
  未命中 101,083；输出 26,842（推理 18,988）。24 条引文、0 未核；
  26 人次角色、21 条关系。
- **命中率低是结构性的，不是提示词问题**：不可省 miss = 首调整个前缀
  （6.8k）+ 每章新增正文与笔记（约 49k）≈ 56k，选通的上限就是 ~76.5%。
  剩余 44k 是第 19 章那次 **整前缀 0 命中**（in=44,054、cached=0，前后章
  都是 74–90%）——prompt 与上章完全一致，属 provider 缓存被逐出/未写入。
  短书对这类抖动极其敏感：一次全 miss 就吃掉 18.6 个点。
- 质量：第 13 章 3 角色 3 关系 5 事实 3 引文、第 20 章（结局）3 角色
  3 关系 5 事实 3 引文，结局/遗言/日记三层都抓到了；`roleplay_kernel`
  跨 8 章合并为 7 个角色、12 条关系、逐字声音样张 8 条，别名
  `舅妈→某角色`、`某人→某人全名` 正常归并。

**认路地图（2026-10-30）**：「前 n 章读到哪了」作为可消费资产，分两级，
**不接回逐章阅读循环**。

- **逐章行（零成本）**：`store.chapter_map()` 纯投影
  `第 n 章 标题：compact`，80 章约 8k 字。随 `as_of` 切片，越界即截掉；
  超出预算先丢最早的单章行，保留卷图和最近章节。
- **卷级图（每 8–10 章一次调用）**：`reading/map.py::build_arc_maps()`，
  输入「上一张图 + 本卷逐章行」，输出一张 <=500 字的定长路标图，落
  `reading_maps`（book_id, level, start_chapter, end_chapter）。
  `scripts/build_reading_map.py 参考书B [--arc 8]` 独立进程跑。
- **卷图是累积的**：第 k 张覆盖「全书第一章 → 本卷末」，所以消费时
  **只取截至 as_of 的最新一张** + 它之后的逐章行；十张拼起来会把同一段
  历史重复十遍（参考书B实测 5,878 字 vs 986 字）。代价是早期细节逐卷被
  压掉，需要时靠 `search_book` 回查——这是「定长地图」的必然取舍。
- **消费**：`roleplay_kernel(..., map_text=)` 与 `scene_view(...,
  map_text=)` 在正文前挂地图（分别占预算 40%/50%，太挤就整块丢）；
  `map_for(store, book_id, as_of)` 是统一入口（最新卷图 + 其后的逐章行）。
- **换窗**：`_reset_context` 先尝试合成一张覆盖全部旧章的图，成功就用
  `<reading-map>` 当摘要块并存 `level='reset'`；合成失败退回原来的
  compact 拼接——换窗绝不因合成失败而失败。
- **为什么不是「每章压一次」**：那等于每章重写上下文，前缀缓存从
  system 之后全部失效；参考书B实测口径下未命中成本约 **2.4 倍**（6.35M
  输入里 93.5% 是 1/50 价买的），调用次数翻倍，且原文 → 笔记 → compact
  → 地图的三级压缩在 80 轮后必然漂移。地图资产用投影 + 低频合成就能
  拿到，不需要牺牲缓存与原文召回。卷级重写（每 8–10 章）是折中：8 次
  全 miss，成本几乎与现状持平，但地图仍是卷级而非逐章。

**参考书B实测（80 章 / 10 卷，2026-10-30）**：10 次调用，输入 12,498、
输出 47,885（推理约 4k/次，单次 65–173s）。输入只占阅读全本 6.35M 的
0.2%，但输出相当于阅读全本的 38%——**地图合成是推理重、输出贵**的
任务；`reading.map` 调用点应绑更便宜的模型（ProviderStore 路由），
或把 `ARC_MAX_TOKENS` 收紧，下一轮处理。各卷 475–617 字；全书地图
（最新卷图 + 尾部 3 章逐章行）986 字 ≈ 700 tokens，可直接塞进伴读/
扮演的头部。

**尚未做**：

- 笔记 → graph.db 的投影脚本（角色 / 关系 / 引文 / 事实），以及别名归一：
  第 7 章「情人」与第 8 章「汤森」靠模型 aliases 合并；模型没抄原称呼时
  仍需投影层归一。
- 写作透镜的消费契约；场景解释的问答侧（当前只有 `scene_view` 纯投影）。
- 服务内接入与并发。原型是独立进程，避免 `api_server` 事件循环被
  `getaddrinfo` executor 冻住（同 `run_graph_extraction.py`）。

**为什么不是继续扩 BookGraph**：现有 Explorer 按 8 块批量提取，看不到
整章/整本的连续语境；adjudicator 逐条断言导致输出约为输入的 2 倍；
结构化图谱适合跳转与检索，不适合作为「读懂这一章」的主产物。阅读会话
把「读」放在前面，图谱只从笔记投影，避免为可视化牺牲阅读姿势。

**2026-10-29 补充**：飞行记录仪已有 `system_prompt` / `messages_json`，
本次把阅读会话接进去（`reading/session.py::_record_call`），并在提示词
版本变化时 bump `READING_PROMPT_VERSION`；下一步可直接对比同一章不同
版本的 `system_prompt` 与调用轨迹来微调提示词/工作流。

**首轮飞行记录仪发现**（v2）：第七章模型并行搜「汤森 / 查理」——那是
第八章才揭晓的名字，工具按 `current_chapter` 正确返回空，但它仍换关键词
继续试探，一章花了 3 次调用。v3 在 `search_book` 的空结果里明说
「不要用后文或全书知识补全」，并在阅读纪律里禁止用预训练知识补全人物
姓名/关系/结局；`coverage` 也标注「不要每章调」。v3 首章复测：**1 次
调用、0 次工具调用**（v2 同章 3 次）；输出 3,084（推理 2,347）。因为
system 提示变了，首调缓存 0 命中，属预期。但同一章重跑时 call 1 仍发了
3 个 `search_book`（缓存命中 2,360），说明模型仍会用预训练名字试探；
空结果提示只在看到结果后生效。要再降调用，需在工具层直接识别「未来章
才出现的名字」并返回 `future_name` 标记，或在系统提示里给出本章人名白
名单——留给下一轮。v4 顺带修正任务里的已读编号：原文首章会写成
「已读：第 1–0 章」，现改为「此前 N 章；本章 X/Y（章节索引 Z）」。

**任务文本与系统提示分开版本**：`READING_PROMPT_VERSION` 只标系统提示；
本次 v4 同时改了 system 的预训练知识禁令与逐章任务文本，因此一并 bump。

**v3 的时延**：首章 105 秒；随后 20 章 / 10 章试跑都在第 7–9 章遇到
一次超过 240 秒的长尾，说明端点偶发长尾。阅读会话改为 240s 总预算 /
150s 空闲、最多 3 次尝试，单章失败记入 `failures` 并继续下一章，不拖垮
全本。全本验收需要端点稳定的时间窗；否则会产出大量 `partial`。

**时延护栏**：单次输出预算从 bookgraph 的 64k 降到 16k 起（撞顶翻倍），
HTTP 超时 **480s 总、不设空闲上限**（`sock_read=None`）。之前设 150s 空闲
上限是错的：非流式请求在服务端生成完之前一个字节都不发，参考书A首章 7.3k
字直接被判成 socket 超时。单章失败记 `failures` 并继续，不拖垮全本。

**上下文模式**：`--context-mode full|compact`。默认 full（完整笔记进上下文，
连续性最好）；compact 只把 compact 进上下文、完整笔记只落库，预计每章
少 ~700 tokens 的一次性 miss。两种模式都保留同一套工具/剧透门，等全本
对比笔记质量与未命中后再定默认。

**缓存账的硬边界**（全本实测后修正）：80 章未命中 416k，其中每章新
正文 + 新笔记约 2.5k（约 200k），其余约 216k 来自 provider 的缓存尾部
/写入滞后——第 11、17 章命中只有 20%、48%，而同一前缀的前后章都正常。
命中率 93.5%，离 95% 差 1.5 个点；compact 模式每章少 ~700 tokens，能
省约 56k，但能否补上这 1.5 点要看 provider 的尾部行为，不能保证。

### 126. 高亮：引文分级，不建表

**结论**（2026-10-30）：高亮就是笔记里的引文，只是多了 `kind` / `tag` /
`who` 三个字段；检索是纯函数 `highlights_for()`，不建表、不改锚点。

- **两种价值**：`literary`（值得学写法——意象、比喻、反讽、对白潜台词、
  自由间接引语、节奏）与 `kernel`（暴露人物内核——欲望-恐惧、自欺、
  决断点、关系反转、认知落差、掩饰）。判据写在 system 里：引文不是
  「情节重要的句子」，两种都不是就**不写**；没有引文的章节很正常。
- **受控词表 12 个**（`prompts.QUOTE_TAGS`），词表外记 `other` 但保留
  kind——`other` 占比高说明该改词表，不是模型的错。
- **不设 kind 配额**：逼模型凑 literary 会产出比没有更糟的高亮。
- **表示**：逐字片段是唯一真源，章/块锚点是加速器。**不存绝对偏移、
  不存 CFI**——重切块就失效；需要 CFI 时按片段现算。同一章重复引文按
  `sha1(归一化文本)[:8]` 去重。
- **v5 起直接产出**；v4 及更早的笔记（参考书B/参考书A全本）走
  `scripts/tag_reading_quotes.py` 回填：只送已逐字核对的引文，每 8 章
  一次调用，写回 `note_json` 并记 `quote_tags_version`。
  全本重读要 6.35M 输入，只为重新打标不值。
- **验收**：gold set（`data/eval/`，不入库不提交，两本书各 25 段、
  正负各半）→ 精度 ≥70%、召回 ≥60%、同章重跑 top-3 Jaccard ≥0.6。
  盲评等写作透镜接上再做。

**回填实测（2026-10-30）**：参考书B 244 条引文 → literary 38 / kernel 73 /
other 133；参考书A 24 条 → 1 / 15 / 8。`other` 过半是预期——v4 的引文按
「情节重要」选，不是按写法选；v5 起才直接产出分级引文。literary 初版
标注太宽（62 条），加「技法必须从这一句本身看得出来」后降到 38 条。

**调用点选路**：`reading.tag` 与 `reading.map` 已绑
`deepseek-v4.1-flash`（控制台路由，p_89de5caa）。实测打标单次
260s → **13.9s**（19 倍）；地图换 flash 后单卷抽检 506 字，结构与
豆包版可比（这一发没落飞行记录仪，时延未入账）。`reading.session`
仍留主模型——笔记是主资产，换模型要先 A/B。
